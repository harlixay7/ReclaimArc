7. LARGE-FILE RESULTS
---------------------
- Sequential Throughput: Exceeds 200 MB/s sustained (207.62 MB/s on 1 GB archive).
- I/O Multiplication: Total physical disk I/O per extraction cycle is 3x the logical archive size (1x pre-test CRC verification + 1x disk extraction write + 1x read-back disk verification). Despite this 3x safety cycle, the entire 1 GB extraction finishes in under 5.0 seconds.
- Memory Scaling: Flat and constant at ~13.75 MB working set regardless of whether extracting 256 MB or 1 GB files.


8. MANY-SMALL-FILES RESULTS
---------------------------
- Scaling Model: Strictly linear O(N) with entry count.
- Per-file Overhead:
  * 100 files: 60.4 ms / file
  * 1,000 files: 56.7 ms / file
  * 5,000 files: 37.2 ms / file
  * 10,000 files: 38.4 ms / file
- Root Cause of per-file duration: Each individual file undergoes (1) SQLite journal transition, (2) NTFS file allocation, (3) disk flush via FlushFileBuffers, (4) read-back BLAKE3 disk verification, (5) atomic rename.
- Throughput: Scales from 16.5 files/sec (cold NTFS MFT) up to ~27 files/sec sustained on large archives.

Finding 1: Per-File Flush & Verification Invariant (37�57 ms per file)
- Evidence: Workloads B1�B4 scale directly with file count at ~26 files/sec.
- Measured Impact: 10,000 small files require ~6.4 minutes.
- Confidence: CONFIRMED BOTTLENECK.
